# Security Policy

## Supported Versions

Security fixes are provided for the current released minor version. Older
versions may receive fixes at maintainer discretion.

## Reporting A Vulnerability

Do not open a public issue for suspected vulnerabilities.

Report security issues to:

```text
support@iyzitrace.com
```

Include:

- Affected version or commit.
- Reproduction steps.
- Impact and affected deployment mode.
- Any known mitigations.

Maintainers will acknowledge reports within five business days when possible.

## Secret Handling

Do not commit:

- `.secrets.env`
- local databases under `data/`
- rendered bundle output
- TLS private keys or generated certificates
- production API keys, JWT secrets, cloud credentials, or tokens

Bootstrap certificates generated by the local stack are for development only.
Rotate any certificate or key material that was ever committed to Git.

## Production Guidance

- Use trusted TLS certificates and rotate bootstrap certificates immediately.
- Store secrets in a dedicated secret manager where possible.
- Review API key enforcement before exposing ingestion or query endpoints.
- Keep Docker base images, Helm dependencies, Go modules, and npm packages
  updated.
