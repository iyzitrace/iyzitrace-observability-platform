# Governance

IyziTrace Observability Platform uses maintainer-led governance.

## Maintainers

Maintainers are listed in `MAINTAINERS.md`. They are responsible for:

- Reviewing and merging pull requests.
- Setting release scope and timing.
- Maintaining project quality and security posture.
- Managing labels, milestones, and roadmap discussions.
- Resolving technical disagreements.

## Decision Making

Routine changes are approved through pull request review. Larger changes should
start with an issue or design note covering motivation, compatibility, rollout,
and test strategy.

When consensus is unclear, maintainers make the final decision based on project
scope, maintainability, security, and user impact.

## Releases

Releases are cut by maintainers. Bundle and CLI releases use tags named
`bundle-vX.Y.Z`. Release notes should include compatibility notes, migration
steps, known issues, checksums, and artifact links.

## Becoming A Maintainer

Maintainers may nominate contributors who consistently provide high-quality
reviews, patches, documentation, or operational support. Maintainer changes
should be reflected in `MAINTAINERS.md` and `.github/CODEOWNERS`.
